## 1. 源库究竟解决什么

OSM（OpenStreetMap）提供真实地理要素：坐标、道路连线、建筑和水域轮廓，以及名称和分类等属性。它不是一张只能整体修改的图片，也不保证覆盖现实中的全部信息。

prettymaps 把这些地理要素组织成可定制的地图作品：指定区域，利用 OSMnx 获取地物，筛选图层和标签，通过 Shapely 等工具进行几何处理，使用 Matplotlib 绘制颜色、线宽、纹理和构图。输出可保存为 PNG 或 SVG 等形式。图层及标签筛选属于基础能力；任意业务条件筛选和交互式编辑需要我们开发。

主要价值是“选择哪些内容、怎样表达”，文件格式转换只是最后一步。它不原生理解自然语言，也不是导航、城市规划、三维建模或完整交互地图系统。GPX/KML 是轨迹输入能力，不等于路线规划能力。详细证据与验证状态见能力清单。

## 2. 我们已验证到哪里

- 西湖：7 张场景成品和 6 张受控能力对照图；本地服务支持修改标题、主题、图层后实际重新绘制。
- 西安：真实 OSM 快照支撑 5 张成品，包括街区介绍、旅行纪念卡、骑行纪念版式、浅色文章图、深色网站图。
- 策划 GPX：从真实道路计算示意线，写入 GPX 并经库读取绘制。它不是用户实骑记录，也不是通行路线推荐。
- 项目补充：中文标题、地标编号、版面组织、快照缓存、生成记录、网页控件和下载。西安道路请求失败后以原始 OSM ways 导入补齐，具体方法见陕西场景记录。

总计 18 张本地成品与对照图；作者示例单独列出，不计入本地复现。未实现自然语言调用、通用路线规划、方案编辑或空间决策产品。

## 3. 大模型应该放在哪里

有三条不同路线：

| 路线 | 原理 | 适用与边界 |
| --- | --- | --- |
| 确定规则绘图 | 真实数据 → 明确参数 → 程序绘制 | 当前实现；可以追溯输入、复现几何与样式 |
| 大模型组织绘图 | 用户意图 → 受约束配置 → 校验 → 数据与算法工具 → 预览修改 | 后续产品方向；模型负责理解与组织，距离、路线等由算法计算 |
| 图像模型重绘 | 地图图片 → 生成式改图 | 可用于艺术表达；不能默认保证地理轮廓、文字和拓扑准确 |

开发阶段可借助大模型编写或改造绘图模块；产品运行阶段也可以让模型调用这些模块。二者独立，并非必须在线调用模型才能生成地图。复用 prettymaps 与参考其思路自建绘图模块，都是可选实现方案。

## 4. 后期意义：共享能力，而不是只积累地图皮肤

我们的潜在基座是“真实空间数据 + 可核查的分析与绘制 + 内容编辑 + 自然语言操作”。prettymaps 可以作为其中一个绘图组件，不能直接等同于整个基座。

| 共享能力（待建设） | 可复用资产 | 产品价值 |
| --- | --- | --- |
| 数据接入、版本与来源管理 | 区域快照、标签分类、业务数据接口 | 多个场景使用一致、可追溯的数据 |
| 查询与空间分析 | 距离、范围、覆盖和路线工具 | 从展示位置发展到回答空间问题 |
| 图层与内容编辑 | 点位、轨迹、照片、文字、任务区域 | 用户能修改自己的方案 |
| 绘图与排版 | 风格、画幅、图例、导出模板 | 不同用途共享输出能力 |
| 方案保存与比较 | 配置版本、指标和前后对照 | 支持迭代与比较，而非只输出一次图片 |
| 大模型入口 | 受约束的操作协议、校验与修改记录 | 用自然语言组织以上工具，结果仍可检查 |

由此可以扩展城市文章配图、旅行记忆、活动与研学策划、设施覆盖和候选地点比较、空间概念设计、真实街区游戏关卡等方向。不同产品仍需要各自的数据、规则和验证；OSM 本身不足以提供实时通行、人口需求、商业成本、历史变化或工程设计条件。

规划需要目标、约束与算法；设计需要方案编辑和专业条件；游戏需要玩法、节奏和虚构内容。它们属于在地图基础上叠加的业务层，不应列成源库已具备的能力。当前没有市场规模、付费意愿或收益验证。

## 5. 推进建议与验收

先行产品建议为“城市内容与探索策划工作台”：以已有西安区域为起点，选地物、加地点和文字、导出作品；随后加入路线编辑与方案比较。策划路线与实际轨迹应使用不同标识。

1. **主题地图编辑**：保存范围、图层、地标、标题、样式；重开后可恢复并导出一致结果。
2. **第二场景复用**：用同一数据接口和编辑操作制作文章配图与探索活动方案，记录必须新增的业务逻辑，验证是否真的形成共享基座。
3. **自然语言入口**：模型只生成受支持操作，参数校验后执行；用户可预览、修改和撤销。
4. **分析与比较**：按明确需求加入路线或覆盖算法，公开输入条件、指标含义和缺失信息，再拓展规划与设计用途。

不以产品数量衡量进展。关键指标是能否复现输出、能否解释数据来源、第二个场景是否真正复用已有能力，以及用户能否完成一个具体任务。
