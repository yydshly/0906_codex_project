# AI Agent Book 系统学习与练习指南

> 目标不是读完 10 章，而是形成四种可迁移能力：能解释 Agent、能实现最小闭环、能评估真实效果、能把有效方法迁移到自己的项目。

[返回项目研究](README.md) · [源码与证据](sources.md) · [上游固定版本](https://github.com/bojieli/ai-agent-book/tree/7572c78e8284416d05cd3435c627b1b38c452ff2)

## 先建立正确预期

这套仓库同时包含书稿、独立实验和外部复现轨道。学习时按三个层次推进：

1. **读懂骨架**：先知道输入、状态、工具、输出和验证器在哪里。
2. **运行最小实验**：从无需复杂硬件的入口开始，保留真实轨迹。
3. **迁移到自己的任务**：替换数据和任务，比较迁移前后的结果。

第一遍可以跳过模型厂商适配、展示层、长期开跑脚本和大型训练框架。能读懂全部代码不是进入下一阶段的条件。

## 开始前准备

- Python 3.11–3.13，以及上游推荐的 uv。
- 一个可以使用的模型接口；具体实验是否支持某个 provider，以实验 README 为准。
- 能阅读 Python、JSON 和基本终端输出。
- 一份学习记录，持续保存问题、输入、轨迹、结果、成本和结论。
- 先使用 CPU 友好实验。CUDA、模拟器、语音和机器人在专项阶段按需准备。

## 六周系统路线

### 第 1 周：理解最小 Agent 和上下文

阅读：[第 1 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter1.md) → [第 2 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter2.md)。

重点掌握：

- Agent、LLM、上下文、工具、Harness 和环境分别负责什么。
- assistant → tool_call → tool_result → assistant 的消息循环。
- Prompt、历史、Skills、工具描述和检索材料怎样共同占用上下文。
- KV Cache 为什么要求稳定前缀，压缩为什么可能损失任务信息。

建议练习：

1. 运行 chapter1/context，比较移除系统指令、工具描述或历史后的行为。
2. 追踪 chapter1/web-search-agent/agent.py 的一轮工具调用。
3. 在 chapter2/context-compression 中选择三种策略处理同一段历史。

本周产物：一张 Agent 循环图、一份完整运行轨迹、一张上下文策略比较表。

通过标准：能够指出每条输入来自哪里；能够解释工具为何被调用、循环为何结束；能够同时报告回答质量和 token 变化。

### 第 2 周：接入知识与记忆

阅读：[第 3 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter3.md)。

重点掌握：

- 用户记忆与知识库的生命周期和权限差异。
- BM25、向量检索、RRF 融合、Reranker 各自解决什么问题。
- Non-Agentic RAG 与 Agentic RAG 的成本和适用边界。
- 原始事实、派生摘要和可变索引为什么要分开保存。

建议练习：

1. 运行 dense-embedding 和 sparse-embedding，观察各自擅长的问题。
2. 运行 retrieval-pipeline，查看 dense / sparse 排名如何融合与重排。
3. 准备 20 个带标准来源的问题，比较单路检索和混合检索。

本周产物：一个带引用的知识问答原型、一份召回与引用准确率报告。

通过标准：答案能定位到来源片段；无相关证据时明确拒答；能够解释一次遗漏发生在解析、召回、排序还是生成阶段。

### 第 3 周：设计工具和 Coding Harness

阅读：[第 4 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter4.md) → [第 5 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter5.md)。

重点掌握：

- 工具 schema、参数验证、错误语义、权限和结果验证。
- MCP 解决连接问题，业务安全仍由服务端和 Harness 保证。
- Coding Agent 的“读 / 搜 → 补丁 → 测试 → 修复 → 验证”循环。
- 制品模式为什么能减少模型搬运大量数据。

建议练习：

1. 给一个只读仓库查询函数设计工具 schema。
2. 测试合法请求、缺失参数、未知工具、超出目录和工具失败五种路径。
3. 用 Coding Agent 完成一个小修复，保存修改前后测试结果。

本周产物：一个有安全边界的工具、一个可审阅补丁和验证记录。

通过标准：工具错误不会让循环失控；模型无法绕过程序权限；交付包含 diff、测试和剩余风险。

### 第 4 周：扩展交互并建立评估

阅读：[第 6 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter6.md) → [第 7 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter7.md)。

重点掌握：

- 异步任务、事件、中断、取消确认与恢复。
- 语音、GUI 和机器人怎样扩大观察与动作空间。
- reset → run → snapshot → verifier → record 的评估闭环。
- 最终失败、过程违规、成本、时延和人工接管是不同指标。

建议练习：

1. 从 async-agent 的离线或本地入口观察一次中断与恢复。
2. 为前两周的知识 Agent 建立 20–30 个固定任务。
3. 保存每次运行的输入、轨迹、输出、验证结果和失败归因。

本周产物：一份 Agent 评估报告，包括成功样本、失败样本、成本和边界。

通过标准：任务环境可重复重置；验证器不依赖模型自称完成；失败能定位到第一处关键错误。

### 第 5 周：理解训练和持续进化

阅读：[第 8 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter8.md) → [第 9 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter9.md)。

重点掌握：

- 什么时候修改上下文、知识、程序，什么时候才值得训练参数。
- SFT、RL、蒸馏的训练信号、留出集与样本效率。
- 轨迹必须先验证，再产生候选更新。
- 边界集、保留集、安全集、灰度和回滚怎样控制更新风险。

建议练习：

1. 从重复失败中提炼一条最小规则。
2. 建立训练样本、边界样本和保留样本，避免同题验证。
3. 比较更新前后成功率，并检查其他任务是否退化。

本周产物：一项可回滚的 Prompt、Skill 或程序规则更新。

通过标准：更新依据可追溯；没有使用评估集训练；退化时能够恢复旧版本。

### 第 6 周：多 Agent 协作与最终迁移

阅读：[第 10 章](https://github.com/bojieli/ai-agent-book/blob/7572c78e8284416d05cd3435c627b1b38c452ff2/book/chapter10.md)。

重点掌握：

- 哪些任务可以独立并行，哪些任务存在先后依赖。
- worker 上下文隔离、消息信封、取消、幂等结算和独立审核。
- 多 Agent 的价值必须用总时间、总成本、成果质量和协调开销衡量。

建议练习：

1. 选择一个研究任务，预先写明拆分方式和验收规则。
2. 分别运行单 Agent 与多 Agent，保持模型、任务和资料一致。
3. 比较完成质量、墙钟时间、总 token、重复工作与人工返工。

本周产物：单 / 多 Agent 双臂报告，以及迁移到自己项目的设计。

通过标准：结果可以说明并行产生了什么收益或损失；审核者使用独立证据；失败结果原样保留。

## 值得优先掌握的技能

### 必修基础

1. ReAct 与工具调用循环。
2. 上下文选择、压缩和缓存边界。
3. BM25、向量、融合与重排序。
4. 工具 schema、权限和错误处理。
5. 环境重置、Verifier 和失败归因。
6. 版本、轨迹、manifest 与负结果记录。

### 工程进阶

1. Coding Harness 与工作区隔离。
2. 异步事件、中断、取消和恢复。
3. 轨迹学习、回归、灰度和回滚。
4. 多 Agent 分工、隔离、通信与审核。

### 按需专项

1. SFT、RL、蒸馏与训练数据工程。
2. 多模态、语音、Computer Use 与机器人。

如果当前目标是开发实用 Agent，优先完成必修基础和工程进阶。后训练需要稳定任务、足够失败数据和可信评估集；机器人还需要硬件、仿真和动作安全条件。

## 每个实验的学习方法

对每个实验固定回答以下问题：

1. **问题**：实验想验证什么假设？
2. **变量**：对照组与实验组只改变了什么？
3. **输入**：任务、数据、模型和环境版本是什么？
4. **循环**：模型、程序、工具和验证器分别做什么？
5. **证据**：原始轨迹、指标、hash 和失败样本在哪里？
6. **结果**：提升是否显著，是否出现负结果？
7. **边界**：结论不能推广到哪些条件？
8. **迁移**：在自己的任务中，需要替换什么并重新验证？

## 适合本研究库的第一项练习

以 001-nihaixia 的资料作为语料，准备 20–30 个带标准答案和来源的问题，保持模型、问题和预算一致，比较：

1. 直接文件检索。
2. BM25 + 向量 + Reranker 的混合检索。
3. 可以多轮改写查询的 Agentic RAG。

至少记录答案正确率、引用准确率、无依据声明、耗时、输入 / 输出 token 和人工纠正次数。这个实验完成后，再决定复杂检索和多 Agent 是否值得进入研究库的长期工作流。
