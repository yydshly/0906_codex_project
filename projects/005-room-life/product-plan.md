# 写实人物产品路线与后续优化清单

2026-09-07 更新。目标已由风格化房间角色升级为接近摄影效果的可交互数字人。本文为后续计划，未完成项不计入已有能力。

[人物形象设计方案](character-design.md) · [历史优化记录](optimization-log.md) · [当前演示说明](README.md)

## 当前基线与目标差距

当前已有原创 V2、有限衣橱、本地一套形象保存、房间八项动作和状态规则。O12 的 35 项测试及真实浏览器 8 / 8 验证只说明限定原型可以运行，不能证明人物达到摄影级品质。

继续保留 V1 完整留档及 V2 功能原型。任务命令、物品归属、占用规则、保存语义和回归场景可以参考复用；人物模型、材质、头发、绑定和运行渲染需要按新目标重做或适配。采用新引擎时，现有 JavaScript 代码不视为自动兼容。

产品目标：用户拥有辨识度稳定的写实人物，能选择发型与穿搭，保存形象并在房间里活动；长期再扩展养成、记忆与剧情。AI 图片和短片可用于确定目标，不替代可操作三维角色。

## 优先级与阶段交付

| 阶段 | 后续要做的工作 | 具体交付与验收 | 前置条件 |
| --- | --- | --- | --- |
| P0 · 外观标准 | 确定写实方向、人物身份、脸与全身参考、光照标准 | 一份角色说明和统一多视角参考；用户认可的目标外观 | 人物年龄表达、性别表达、风格尚未确定 |
| P0 · 制作与运行验证 | 比较原创制作流程、数字人基础与本地或网页运行方式 | 一份设备和工具链记录、一段可旋转的实时头肩样板 | 核对实际硬件、预算与第三方基础的接受范围 |
| P0 · 头肩真实感 | 面部结构、眼球、皮肤、头发、肩颈、基础表情 | 多角度、多光照下保持同一人；实际眨眼和转头；区分离线与实时画面 | 外观标准确定 |
| P1 · 全身与第一套服装 | 身体比例、手部、骨架、蒙皮、衣物版型和材质 | 同一人物全身站立、走路、坐下、拿杯子，检查关节和穿插 | 头肩样板达到认可标准 |
| P1 · 形象定制 | 发型与换装适配、独立配色、组合规则 | 两种发型、两套服装可换，近景及动作检查通过 | 统一身体和骨架 |
| P1 · 房间动作整合 | 重做或适配走跑、起停、抓握、坐起、上下车 | 完整八项体验与中断场景；不能因模型更换重现下跪、物品复制或占用错误 | 新身体和服装可运行 |
| P1 · 运行品质 | 细节层级、资源加载、阴影、长时间运行与设备适配 | 在约定设备和分辨率下记录帧率、延迟、内存及恢复行为 | 尽早做预算，随样板和全身阶段持续检查 |
| P2 · 角色与世界存档 | 多套命名形象、缩略图、版本迁移、世界状态保存 | 刷新和升级后正确恢复，换装不丢任务，角色身份稳定 | 基础外观结构稳定 |
| P2 · 生命感与养成 | 微表情、自然视线、呼吸、日常偏好、关系与任务反馈 | 角色有可理解的状态变化和持续反馈 | 先明确产品玩法，不凭动作数量代替养成 |
| P3 · 内容与智能扩展 | 更多家具、物品、角色；对话、记忆及动作计划 | 第二种物品通过配置适配，语言指令经规则检查执行 | 可靠交互和存档闭环 |

P0/P1/P2/P3 表示实施顺序，不是工期。性能验证贯穿各阶段，不等到全部内容做完才检查。当前没有团队产能、设备与预算基准，不给确定工期或成本数字。

## 动作方面仍需保留的优化

动作细节退到写实人物基础之后，但已知问题需要继续记录。

| 范围 | 待解决内容 | 验证场景 |
| --- | --- | --- |
| 行走与跑步 | 用新腿长重新标定步幅、骨盆、摆臂；改善急转纠正性滑步、反向和走跑过渡 | 首帧起步、短停重启、急转、靠墙、低帧率和不同速度 |
| 身体与服装变形 | 肩、肘、髋、膝弯曲的体积和衣物折叠，减少衣服穿入身体 | 抬臂、屈肘、跨步、深屈膝和坐姿近景 |
| 抓握与放置 | 手指贴合、视线提前对准、手臂避开桌面、放稳后松手 | 拿放交接前后取消、持物走跑、不同物品尺度 |
| 坐起与上下车 | 脚、手、臀部的支撑顺序和接触，不穿过椅子与车体 | 各动作中段慢放、取消、占用冲突与不同座位尺寸 |
| 面部与生命感 | 眨眼、眼球和头部协调、自然微笑、说话时口型与表情 | 多光照近景和连续动作，检查眼神空洞与机械变化 |
| 环境与镜头 | 房间材质、比例、光照和人物统一；观察及换装时不遮挡 | 正侧背、全景、家具附近和窄屏操作 |

目前已有脚部接触和两段肢体求解，不需要把它们重复列为“完全未实现”；新角色上线后需要重新验证其适配与边界。

## 明确的风险与处理顺序

| 风险 | 为什么可能阻塞 | 最早验证方法 |
| --- | --- | --- |
| 美术目标不一致 | 每轮仅凭“更真实”调整，难以判断完成 | 第一阶段固定参考与同镜头对照 |
| 内容制作能力不足 | 提示词或代码不能自动保证拓扑、皮肤、头发及变形质量 | 先完成头肩样板，暴露制作短板 |
| 好看但不能实时运行 | 离线渲染不受交互帧时预算约束 | 同一模型分别记录静态和实时结果 |
| 写实外观配机械动作 | 外观提升后微小动作错误更明显 | 在头肩阶段就测试眼神、眨眼与转头 |
| 换装破坏接触 | 不同体型、衣物或鞋高改变肢体关系 | 首版固定体型和鞋底高度；扩展时增加兼容检查 |
| 网页运行与画质冲突 | 本地设备能力或串流网络限制最终体验 | 样板阶段比较本机渲染与浏览器入口；测量实际结果 |
| 人物变更导致旧存档失效 | 旧部件可能不适配新身体版本 | 为人物和部件记录版本及回退搭配 |

制作工具与运行设备需分开评估：编辑器硬件要求不等于最终用户最低配置。MetaHuman 官方对各功能列出了硬件要求，实际采用前需按具体功能核对。[官方硬件要求](https://dev.epicgames.com/documentation/metahuman/metahuman-hardware-requirements-in-unreal-engine)

## 本轮之后最值得执行的任务

先制作“原创写实人物设计包”：三种气质方向的候选参考、一个确定的人物身份、多视角面部与全身参考，以及头肩样板验收表。随后只实现一名人物的实时头肩样板，先证明外观和运行路线。

近期暂停扩大当前卡通形象的发型与服装数量。先保留功能原型，待新人物品质成立后再移植衣橱和生活流程。具体设计方法见 [人物形象设计方案](character-design.md)。

这次只完成路线整理，未生成角色参考图、制作照片级模型、采购内容或启动新引擎部署。
