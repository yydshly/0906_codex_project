KEY QUESTION / 资料怎样成为可用数据

保存为 Markdown 之后，还需要什么？

下面是我们建议补建的数据生产流程，尚未在本项目实现。

  1. 01 · 解析与整理取得准确的内容

    保留原件、阅读顺序、章节和表格；按结构分段。

  2. 02 · 抽取与统一形成标准记录

    提取对象、字段、条件与例外，统一名称、单位与版本。

  3. 03 · 校验与追溯每条数据有依据

    检查重复、缺失和冲突，关联原文位置及核验状态。

  4. 04 · 按任务提供让上层能查能算

    文本检索用于解释，结构化查询用于统计，关系索引用于关联。

02 / REFERENCE ARCHITECTURES

按问题选方案，不把所有工作都交给 RAG

参考方案尚未接入。下面是我们的选型分析，不是性能实测。

RAG = 检索相关资料，再让模型基于资料生成回答。

资料解析解决“内容能否正确取出”；检索解决“能否找到依据”；生成解决“如何组织回答”。这三层需要分别验证。

03 / VALUE TO OUR LAB

它的价值，是示范如何组织可复用的专家经验

最值得借鉴的是组织方法；回答准确性仍需要独立验证。

01 / 知识资产

资料有层次，也有入口

长文、案例、速查与索引分开。我们可以把源码解读、复现记录和技术资料整理成可检索的研究档案。

02 / 方法资产

不仅记结论，也记判断步骤

把适用条件、比较顺序和例外写清楚。可迁移到选型、故障排查与方案评审，并保留原始依据。

03 / 产品复用

同批资料支持不同使用方式

供模型检索解释，也能转成数据支持查询界面。稳定且可验证的规则可以进一步写成程序。

建议的下一步 · 尚未实施

用一份真实资料，验证从原文到回答的完整过程

保留原件与页码 → 按结构整理 → 建立关键词检索基线 → 比较混合检索 → 给出带来源的回答。

验收先看这四件事
  • 提取是否准确、完整
  • 条件与例外是否保留
  • 问题能否检索到正确依据
  • 回答是否忠于依据并可追溯

这个库提供了可研究的样本，尚未提供完整可复现的资料生产服务。我们仍需补齐来源映射、统一数据定义、自动校验与效果评测。

DETAIL / NEXT STEPS

后续建设的优先级

以下为我们的扩展建议，尚未实现。

优先 01

来源可追溯

每个结论保留出处与版本，区分原文、解释和推断。

优先 02

数据可复用

统一字段，清理占位与重复，区分患者和就诊记录。

优先 03

效果可比较

对比普通问答、仅检索、加入流程和人物风格的实际表现。

随后

检索与入口优化

增加别名检索、拆分入口，再测量成本与准确率的变化。

对我们的意义

把项目研究，变成下一次工作的参考能力。

源码解读是知识模块，复现记录是案例库，排查步骤是判断流程。我们可以借鉴这种组织方式，建立带来源、能检索、可验证的项目研究助手。

未来可以回答“我们研究过的项目里，哪些支持离线运行？请给出源码或实验依据。”
