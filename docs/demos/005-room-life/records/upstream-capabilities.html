原库解决什么问题

Nova3D 的定位是把文字或参考图片转为可编辑的结构化三维资产。官方描述的流程是：模型编写 Blender Python，执行、检查和修复后，输出有命名部件、层级、关节枢轴和材质的 GLB。重点是保留资产的结构与可编辑性。

这是生成系统与工具集成的能力，不是单一大模型本身的能力，也不能据此保证任意输入都产生照片级人物。官方总说明

公开仓库包含什么

部分 官方描述的能力 依赖与限制
Web 客户端 Flutter/Dart 界面，参考图片输入、模型历史缓存、内置 Three.js 编辑视口及材质和变换编辑 连接托管服务；单独启动前端不等于本地拥有生成后端
MCP 集成 将生成流程提供给兼容的 Agent 调用，返回浏览器查看入口 需要完成账户接入及生成条件检查；不是 IDE 内嵌三维视口
Blender 插件 在 Blender 发起文字或图片引导生成，导入分部件模型并保留生成 Python、GLB、UV 等输出 仍依赖托管服务；按所选模式使用服务额度或模型供应商账户
生成后端 官方描述包含代码构造、执行、修复与验证流程 当前闭源；该仓库不提供完整可自托管后端

来源：Web 客户端、MCP、Blender 插件。

我们的扩展与边界

“栖居”从这次调研出发，扩展研究问题到“角色进入房间后如何持续活动”。这是独立原创实验，不是 Nova3D 的 Fork、插件或生成服务复现。没有复用上游代码，也没有导入上游生成人物；当前运行无需 Nova3D 账户、API 密钥或生成服务。

对比 Nova3D 栖居 005
主要目标 生成与编辑结构化三维资产 验证角色、衣橱与生活交互
内容来源 官方描述为模型编写构造代码 本项目手写程序化人物、场景及动作
模型服务 使用托管生成流程 当前未接入
生活行为 不能从资产生成能力推断已有养成玩法 已有走动、拿放、坐起、驾驶及状态规则
写实人物 官方展示不能代替我们自己的验收 当前仍为风格化原型，写实人物是后续目标

上游客户端与集成使用 MIT；闭源服务不因客户端开源而变成 MIT。本项目没有复制上游代码，MIT 也不自动覆盖我们的原创内容。本仓库尚未声明原创内容的统一开源许可证；Three.js、esbuild、marked 的许可单独保留。
